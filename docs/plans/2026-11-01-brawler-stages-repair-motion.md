# SKAND BRAWLER：推进感、护盾补给与主题关卡 Implementation Plan

**Goal:** 在保留 75 秒正式短局和现有移动、跳跃、攻击操作的基础上，让玩家明显感受到前进、经过不同区域，以及受伤后仍有翻盘机会。

**Architecture:** 用独立的正式战斗时钟驱动关卡配置；背景运动、敌人移动与关卡进度分别管理。补给是有实际位置和生命周期的游戏实体，圣物判定使用真实受伤记录。

**Tech Stack:** 当前 React 18、TypeScript、Canvas 2D、Vite、pixelfx，不引入新游戏引擎。

**交付范围:** 本文为用户自行编码的设计与实施方案；本次仅新增方案文档，不修改游戏代码。以下数值是首轮调参起点，不是已验证的最佳值。

## 1. 最新代码依据

- `scripts/skand-brawler/src/game/engine.ts`：背景速度为 `30 + (heroVx > 0 ? 40 : heroVx < 0 ? -15 : 0)`；没有护盾恢复逻辑；通过一个 `waveStep` 循环所有敌人组合。
- `scripts/skand-brawler/src/game/sprites.ts`：远景速度系数 0.12、中景 0.38，道路反光又将近景位移乘 0.3。站立时远景约 3.6、中景 11.4、反光 9 个逻辑像素/秒，缺少明显的近景参照物。
- `scripts/skand-brawler/src/game/spec.ts`：正式时间设为 75 秒，68 秒出现核心；护盾上限概念目前只有初始值 3；黄金摇杆以剩余 3 盾和核心击破判断无伤。
- 当前教学已经是任务门槛式教学，并且教学受击不扣盾，但 `gameTimer` 仍在教学期间增长，68 秒的核心判定也未被教学状态隔离。慢速教学会吞掉正式流程，甚至可拖入终局。

## 2. 总体流程与时间规则

推荐：首次可跳过的安全教学 → 75 秒正式挑战 → 结算。

- 教学不消耗正式挑战时间，不推进关卡，不生成恢复补给，也不累积正式分数、连击、掉落和圣物统计。
- 教学完成或跳过后清理教学敌人、碎片、特效和输入缓冲，重置正式战绩与 3 格护盾，再开始倒计时。
- 记录已完成教学；再次游玩默认直接进入挑战，菜单保留“练习操作”。
- `runTime` 仅在正式挑战且未暂停时推进；本轮沿用顿帧暂停战斗时钟的规则，意味着 75 秒为游戏时间，不严格等于现实时间。
- 主题切换时长包含在 75 秒内，不额外延长；教学则在 75 秒之外。
- 暂停时背景、转场、补给寿命和所有计时器一起暂停。

| 阶段 | 正式时间 | 目标体验 | 补给 |
|---|---|---|---|
| 雨夜街区 | 0–22s | 看清目标、建立节奏 | 无 |
| 制造车间 | 22–46s | 破盾和跳跃组合 | 进入时 1 次 |
| 高架天台 | 46–68s | 空中拦截与高速推进 | 进入时 1 次 |
| 原型核心 | 68–75s | 固定场地，集中终结 | 无 |

## 3. 背景推进感

### 3.1 速度目标

用“每秒经过多少屏宽”描述背景速度，避免桌面和竖屏感受差异过大。仅作用于背景，绝不直接加进敌人或碰撞体速度。

| 状态 | 参考滚动速度（屏宽/秒） | 320 逻辑宽度时约值 |
|---|---:|---:|
| 教学 | 0.12 | 38 px/s |
| 雨夜街区 | 0.25 | 80 px/s |
| 制造车间 | 0.30 | 96 px/s |
| 高架天台 | 0.34 | 109 px/s |
| 核心场地 | 0.04 | 13 px/s |

- 右移时增加 0.08 屏宽/秒，左移时减去 0.04；仍保持向前行进，不倒放整座城市。核心场地不加移动增益。
- 命中后、顿帧结束时触发 120ms 的背景推进脉冲，增益 0.10 屏宽/秒。空挥不触发。
- 连续命中刷新脉冲时长，不累加增益；总参考速度上限 0.50 屏宽/秒。
- 五阶可增加常驻 0.03 屏宽/秒，但不提高怪物接近速度。
- 使用 `1 - exp(-dt / tau)` 平滑接近目标速度，建议加速 tau=0.12s、减速 tau=0.20s；避免按键导致背景瞬间变速。

### 3.2 四层速度分工

| 层 | 相对参考速度 | 内容与限制 |
|---|---:|---|
| 远景 | 0.10 | 天际线、烟囱、远楼，保持稳定 |
| 中景 | 0.42 | 店面、厂房、桥梁主体，负责辨识主题 |
| 路面 | 0.90 | 路缝、短反光、栅格、桥板，提供持续前进参照 |
| 近景 | 1.25 | 稀疏灯柱、栏杆端头、前景短构件，每 2–3 秒一件 |

- 路面不要再额外乘 0.3；使用短而清晰的移动标记，避免当前近乎静止的暗色竖带。
- 近景不能遮住角色、敌人、补给或起跳落点；优先限定在地面下方，低对比度，不横扫整个画面。
- 先提高近景和路面速度，不同时提高雨点密度、招牌闪烁和震屏。
- 所有“世界位移”保留浮点累计值，绘制时取整；按各层图案真实周期取模，不先 `% 1000` 再对另一周期取模，防止加速后出现循环接缝跳变。
- 窗户明暗应绑定建筑 ID 和窗户局部坐标，不用移动中的屏幕坐标做随机种子，防止加速后窗户像跑马灯。
- 减弱动态效果设置下，背景速度约减半、关闭推进脉冲和前景掠过，战斗速度和判定不变。

## 4. 护盾恢复：维修电池

### 4.1 第一版只有一个恢复道具

名称“维修电池”，功能是恢复 1 格护盾，上限 3 格。玩家看到的文案为“护盾 +1”，与现有三格 SHIELDS 保持一致。

- 正式挑战中共有两次补给投放机会，分别在 22s、46s 的换场安全间隙。
- 每个槽位只生成一次；关卡切换重复调用、连续受伤、掉落未拾取，都不能再刷出同一槽位。
- 第一版不使用敌人随机掉血包，不增加应急第三次补给，也不让普通蓝色碎片回血。先保证所有玩家面对相同机会，便于调平衡。
- 满盾时仍可拾取，转成 +250 分，显示“护盾已满 +250”；不叠加第四格护盾，不清空或增加连击。
- 拾取时读取当前护盾状态，不在生成时锁定收益。

### 4.2 投放、移动与拾取

- 先出现 0.35s 的地面投放标记，随后电池用 0.25s 从地面上方约 20 逻辑像素降下。
- 投放在角色前方约 0.20 屏宽，限制到安全可见区域；靠近右边界时改投角色附近的可达空位。
- 背景是装饰性滚动，电池使用与战斗实体一致的坐标；不要再随背景扣一次位移。落地后停留在场地内，只做上下约 2px 的轻微浮动。
- 电池投放后保留 6s；离角色约 0.12 屏宽且高度相近时启动短距离吸附，约 0.15s 内到达；不能隔空从全屏另一端回收。
- 未拾取到期则淡出并消失，不自动回血；对应补给槽位仍算已使用。
- 投放前检查落点和邻近接近路径，不与激光、敌人重叠。波次规划在边界前留出空间，投放可等待最多约 2s 的安全时机；不要为了补给直接删除仍在战斗中的敌人。
- 换场休息区约 1.2–2s 不刷新敌人，冻结连击衰减；旧敌人存在时应延后“安全休息”的开始，不用一刀切暂停旧敌人。
- 同帧处理顺序明确为受击/死亡判定 → 存活者拾取；0 盾后不能靠同帧电池复活。正常存活时回血不会额外刷新无敌时长。

### 4.3 视觉与声音

- 画成明显的短粗电池，外壳浅白、内部青绿，两段充能刻线；与蓝色小菱形分数碎片和金色圣物区别开。
- 不使用长光柱，不留下水晶模型，不套循环拾取演出。
- 拾取后角色周围展开一圈约 180ms 的细护盾环；HUD 中恢复的那一格亮起；一声简短上行电子音；“护盾 +1”约 0.6s 消失。
- 同一屏只允许一个维修电池。切换关卡保留未过期的电池；68s 核心开始时，前面正常投放的电池已自然到期。

### 4.4 加回血必须同步修改的统计

新增 `damageTaken`（实际损失的护盾格数）、`repairsCollected`（电池拾取数）、`shieldsRestored`（实际恢复格数）。

- 无敌、教学保护下未扣盾的碰撞，不增加 `damageTaken`。
- 黄金摇杆条件改为 `damageTaken === 0 && bossDefeated`，不要再以最终剩余 3 盾代替无伤。
- 残血生存圣物继续按最终 1 盾和完成正式挑战判断；文案明确允许期间修复，避免鼓励玩家拒绝必要补给。
- 结算和分享卡可显示“护盾修复 1 格”；满盾转分不算恢复。
- 旧战绩如果没有受伤字段，应显示“未记录”，不能从剩余盾反推无伤；已收藏圣物不撤销。

## 5. 三种主题与终局场景

美术延续 SKAND 像素工业夜景；每个主题同时改变建筑轮廓、路面、环境运动、波次构成和声音层次，不只替换背景颜色。敌人/危险的语义色跨主题保持一致。

| 项目 | 雨夜街区 | 制造车间 | 高架天台 | 原型核心 |
|---|---|---|---|---|
| 主底色 | #070B18 | #15110F | #07151D | #0D1019 |
| 建筑/结构 | #172033 店面楼群 | #292323 管道与桁架 | #13303A 桥梁与天线 | 深灰平台与核心支架 |
| 环境强调 | #4970A6 冷蓝 | #BA8247 暗琥珀 | #5A9FA4 青灰 | #FFD166 金色核心 |
| 路面 | 湿地短反光、路缝 | 钢板接缝、传送带节段 | 高架伸缩缝、护栏 | 稳定平台，低速滚动 |
| 远景 | SKAND 店招、雨夜城市 | 起重结构、排气塔 | 开阔天空、远处城市 | 大型原型设备 |
| 环境运动 | 稀疏斜雨 | 偶发短蒸汽，不能像敌方弹幕 | 稀疏风线，限制在上空 | 核心脉冲，与攻击反馈分开 |
| 敌人重点 | 路障为主，单激光/单无人机 | 护盾怪与激光，加入跳斩收尾 | 无人机与地面穿插 | 20 次命中的额外奖励挑战 |
| 音景 | 低音脉冲、轻雨底噪 | 加入机械节拍、短金属声 | 加入风噪与更明亮的节拍 | 低音收束，命中声成为主角 |

- 珊瑚红仍代表危险；青绿维修电池始终带电池轮廓和地面标记，不仅靠颜色认出。
- 中远景亮度明显低于战斗前景，厂房琥珀色不能与金色暴击同等明亮。
- 第一版每个主题一个标志性结构加一种路面即可，利用现有程序绘图，不先制作大批新素材。
- 第一版不加入风力改变跳跃、滑地、坠落平台等新物理规则，保持主题切换时操作可预测。

### 5.1 波次设计

- 每个主题独立的 `patterns` 和索引；禁止继续共用一个循环数组后只换色。
- 雨夜：两次地面斩击 → 单次跳跃 → 一次无人机 → 留出短休息。
- 车间：护盾怪 → 单激光 → 无人机收尾；三阶一击破盾后应明显感到变强。
- 天台：无人机 → 路障 → 单激光/无人机组合；同时需要处理的主要威胁不超过两个。
- 用“抵达战斗区域的时间间隔”校准组合，而不是只用出生间隔；当前敌人速度不同，宽屏和窄屏的路程也不同。
- 先保持现有怪物速度，用组合调整难度；不要把背景加速直接变成怪物加速。
- 以三阶一击破盾等升级规则计算可得连击，确保优秀玩家能在约 55–60s 达到五阶，而不必等终局凑次数。
- 转场休息期间冻结连击衰减，不因设计上的空档惩罚玩家。

### 5.2 转场方式

- 保持地面高度、角色位置、敌人碰撞不变；不清空护盾、分数或武器。
- 主题边界开始后约 0.8s 插值天空和环境色；建筑结构在下一自然区块接缝替换，或两套背景短时淡变。
- 不在切换时将累计滚动距离清零，避免画面跳回原点。
- 短标题“制造车间 / 2–3”出现约 0.9s，不遮挡敌人和落点；HUD 常驻小型三段进度，核心阶段另标核心图标。
- 68s 不再发补给；背景在约 0.45s 内减速，平台稳定，核心落地，提示“击破核心：额外 +5000”。
- 75s 存活算完成，核心击破算额外成就，继续保留两种结果区别。

## 6. 数据与文件边界

建议最小数据模型：

```ts
type RunPhase = 'TUTORIAL' | 'RUN' | 'RESULT';
type StageId = 'street' | 'factory' | 'rooftop' | 'core';

interface StageConfig {
  id: StageId;
  nameZh: string;
  startAt: number;
  endAt: number;
  scrollScreensPerSecond: number;
  theme: SceneTheme;
  patterns: WavePattern[];
  repairSlot?: 'first' | 'second';
}

interface RepairPickup {
  id: number;
  slot: 'first' | 'second';
  x: number;
  y: number;
  state: 'TELEGRAPH' | 'DROP' | 'AVAILABLE' | 'ATTRACTING';
  age: number;
  lifeRemaining: number;
}
```

`SceneTheme` 保存四层颜色、地面样式、结构类型、环境效果；`WavePattern` 保存敌人序列及间隔。用明确字段，不让主题实现读取 React 状态。

## 7. 建议编码顺序

1. **先拆正式时钟与教学。** 明确开始挑战的唯一入口，重置战绩；验证教学停留超过 75 秒也不触发核心。
2. **只做背景推进感。** 在当前街区加入路面参照与稀疏前景，调速和接缝；不同时改怪物速度，以便判断效果。
3. **做恢复实体与受伤统计。** 可用临时测试入口触发两枚电池；先验证拾取和无伤成就，再接关卡边界。
4. **做阶段配置和三套背景。** 先可手动切换检查画面，再接 22/46/68 秒边界。
5. **配置分关波次、补给窗口和连击保护。** 复算不同武器等级下的有效命中机会。
6. **接 HUD、结算与音景。** 音景属于最后一层润色，不阻塞核心机制。

每步完成后单独检查、记录或提交，避免一次同时调整背景、怪物速度和玩家移动速度，导致无法判断哪项改善或破坏了手感。

## 8. 验收清单

### 逻辑检查

- 教学可停留超过 75 秒；关卡、核心、补给均不启动。完成教学后从 0 秒、满盾、空连击进入正式挑战。
- 21.99/22、45.99/46、67.99/68 秒边界选择正确阶段；边界重复 update 不重复触发补给。
- 受伤到 2 盾、拾取后回 3 盾，再击破核心，不获得“全程无伤”。
- 两次正常拾取最多恢复 2 格；满盾拾取仅加 250 分，护盾不超过 3。
- 未拾取电池 6 秒后消失，不自动恢复；暂停期间寿命不流逝。
- 同帧致死碰撞与拾取不复活；无敌碰撞不计入真实受伤。
- 转场不重置分数/武器，不因休息丢连击，不删除尚在攻击角色的敌人。
- 30/60/120fps 下单位游戏时间的背景距离、补给阶段时长基本一致。

### 画面与手感检查

- 玩家不移动时仍能看到路缝持续经过；右移和命中后推进增强，但可以看清敌人。
- 连续玩完一局，无背景循环接缝跳动、窗户快速乱闪、前景遮挡。
- 街区、车间、天台在不看标题时也能通过轮廓和路面辨识。
- 电池一眼可辨，蓝色碎片不再被误认为回血；拾取后场上无残留模型。
- 至少覆盖 1280×800、390×844、360×640；真机核验多指操作、屏幕安全区及减弱动态效果设置。
- 重开恢复初始关卡和补给槽位，暂停/切后台无计时跳跃，旧图鉴仍可读取。

### 构建

- 在项目根目录运行 `npm run build:play`，预期 TypeScript 与 Vite 均通过。注意该命令会更新 `play/` 构建产物，应由实施者在准备好验证构建时执行。
- 对阶段边界、修复上限、无伤判定补充小范围逻辑测试；美术配色与动画节奏通过实际截图和试玩检查，不写只复述实现的测试。

## 9. 后续扩展，第一版先不做

- 残血时提前兑现“下一次固定补给”，不得额外增加第三枚；需单独验证可重复触发问题。
- 每个主题多个可复现随机组合，用固定种子公平比较分数。
- 通关后解锁独立关卡选择、额外主题、每日挑战。
- 成长道具或临时武器，不与本轮回血机制同时加入，避免无法定位平衡变化。
